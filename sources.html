Read the field with your guard up

Harness engineering is roughly eighteen months old as a named discipline. Its canon is written almost entirely by people selling something adjacent — model providers, framework vendors, consultancies. That does not make the engineering wrong; these are the teams with the most reps. It does mean the framing is not neutral and the negative results are underreported. Read for mechanism. Discount conclusions. Verify by ablation.

Tier 1Read these first

The Anatomy of an Agent Harness

Primary Vivek Trivedy · LangChain · 10 March 2026 · blog.langchain.com

The definitional text. Coins Agent = Model + Harness and derives each component by working backwards from what a model structurally cannot do. The derivation method — behaviour we want → harness design that delivers it — is more valuable than any individual component it derives.

Read it for: the definition, the derivation discipline, the components list.
Discount: it is also a LangChain positioning piece. Framework-shaped conclusions.
Used in: Modules 00, 02, 03.

Harness design for long-running application development

Primary Prithvi Rajasekaran · Anthropic · 24 March 2026 · anthropic.com/engineering

The most valuable single document in the field, because it is the only one that reports removing things and says what happened. Planner/generator/evaluator architecture, context resets versus compaction, the self-evaluation failure, the 6hr/$200 versus 20min/$9 comparison, and the methodical one-at-a-time simplification after a radical cutback failed.

Read it for: the ablation methodology, the honest cost numbers, the components they killed.
Discount: Claude-specific throughout; every finding is entangled with one model family.
Used in: Modules 03, 04, 05, 06, 09.

Harness engineering (the coding agent user's view)

Primary Birgitta Böckeler · martinfowler.com · 2026 · martinfowler.com/articles

The best conceptual scaffolding available. Guides versus sensors (feedforward/feedback), computational versus inferential, the inner/outer harness distinction, regulation categories, and harnessability. Also the most honest about limits — explicit that neither control class reliably catches misdiagnosis, over-engineering, or misunderstood instructions.

Read it for: the two-by-two, the bounded-context framing, the stated limits.
Discount: little quantitative evidence; it is a conceptual paper.
Used in: Modules 00, 05.

Agent Harness Engineering

Primary Addy Osmani · 19 April 2026 · addyo.substack.com

The best synthesis and the clearest writing. Sources the term to Trivedy, pulls together HumanLayer and Anthropic, and articulates the ratchet: anytime an agent makes a mistake, engineer a solution so it never makes that mistake again — with the important inverse about removing constraints models have made redundant.

Read it for: the ratchet, the two-sided rule, the "you can't download it" argument.
Discount: secondary throughout; verify its citations at the primaries.
Used in: Modules 00, 02, 08.

Tier 2Substantial and specific

Skill issue: harness engineering for coding agents

Primary HumanLayer · humanlayer.dev/blog

The most practical of the set. "It's not a model problem, it's a configuration problem." Source of the silent-success verification contract, the CLI-over-MCP decision rule (they replaced the Linear MCP server with a CLI section in CLAUDE.md), the 4,000-lines-of-passing-tests hallucination story, and the tool-thrash negative result on restricting subagent toolbelts.

Read it for: concrete patterns and, unusually, a reported failure.
Used in: Modules 02, 05, 06.

Managed agents / the pets-to-cattle refactor

Primary Anthropic · anthropic.com/engineering/managed-agents

Infrastructure architecture, and the only source treating prompt injection as a structural problem rather than a prompting one. Harness/session/sandbox separation, git auth wired at sandbox init, the credential proxy, the append-only session log that makes compaction reversible, and the cold-start latency numbers.

Read it for: credential isolation, the three-interface decomposition.
Used in: Modules 03, 07.

Effective context engineering for AI agents

Primary Anthropic · anthropic.com/engineering

Context as a finite, degrading resource. Compaction, tool-output offloading, progressive disclosure, and the context-anxiety observation that motivates Module 04's resets.

Used in: Modules 03, 04.

Context engineering for agents

Primary LangChain · blog.langchain.com

Source of the write / select / compress / isolate taxonomy used throughout Module 03. Four buckets, and every technique in the field lands in one of them.

Used in: Module 03.

Six agent harness capabilities for higher model performance

Primary NVIDIA Developer Blog · developer.nvidia.com/blog

A capability-oriented checklist rather than a component list — useful precisely because it surfaces gaps a component list hides, particularly error recovery and observability.

Discount: vendor framing, oriented toward NVIDIA's stack.
Used in: Module 08.

Building effective agents

Primary Anthropic · anthropic.com/engineering

Predates the term but frames the restraint principle every later post quotes back: find the simplest solution possible, and only increase complexity when needed.

Used in: Module 09.

Tier 3Counterpoint, formal work, and code

Stop overengineering your agent harness

Primary Hugo Bowne-Anderson · hugobowne.substack.com

The dissent, and worth reading precisely because the rest of the canon is written by people who build elaborate harnesses. Argues teams over-build scaffolding that each model release invalidates. Module 09 takes the weak form seriously; the strong form does not survive Module 02.

Used in: Module 09.

Harness engineering / HarnessCard

Preprint He et al. · Preprints.org 202603.1756 · preprints.org

The only attempt at formalisation I found. Argues harness configuration is a confound in published agent results and proposes a structured disclosure standard.

Weight: preprint, not peer reviewed, adoption near zero. The argument is sound; treat the standard as a proposal and a good self-audit.
Used in: Module 08.

AI Harness Engineering

arXiv Zhong & Zhu · arXiv:2605.13357 · arxiv.org/abs/2605.13357

The most complete research framing. Relocates the "agents aren't capable enough" gap to the harness, formalizes eleven component responsibilities (task spec, context, tools, memory, state, observability, attribution, verification, permissions, entropy audit, intervention), and proposes the H0–H3 maturity ladder (bare → tool-augmented → verifiable → auditable). Validated via an episode-package evaluation protocol.

Weight: preprint, 2026; I read the abstract, not the full PDF. Used in: Modules 10, 11.

Agentic Harness Engineering (AHE)

arXiv Lin et al. · arXiv:2604.25850 · arxiv.org/abs/2604.25850

A self-evolving harness loop driven by three observability pillars — component, experience, decision. Ten iterations lifted pass@1 on Terminal-Bench 2 from 69.7% to 77.0%, beating the human-designed Codex-CLI harness (71.9%); the frozen evolved harness transferred +5–10pp across three other model families. Ablations localize the gain to tools, middleware, and long-term memory — not the system prompt.

Weight: preprint, 2026; abstract read. Used in: Module 14.

HarnessX

arXiv Chen et al. · arXiv:2606.14249 · arxiv.org/abs/2606.14249

Assembles typed harness primitives via a substitution algebra (composable), adapts them through AEGIS, a trace-driven multi-agent evolution engine (adaptive), and closes the loop by turning trajectories into both harness updates and model-training signal (evolvable). Reports +14.5% average gain (up to +44%) across five benchmarks, largest where baselines are lowest.

Weight: preprint, 2026; abstract read. Used in: Module 14.

What makes a harness a harness

arXiv Macedo · arXiv:2606.10106 · arxiv.org/abs/2606.10106

A constitutive definition — necessary and sufficient conditions for a system to be an agent harness — operationalized as an inclusion/exclusion test. Reconstructs the lineage (tack → test harness → eval harness → agent harness) and closes with a research agenda organized by design-tension axes (generality/specialization, control/autonomy, transparency/performance, stability/adaptability).

Weight: preprint, 2026; abstract read. Used in: Module 10.

Microsoft Agent Framework

Repo Microsoft · github.com/microsoft/agent-framework · docs

The closest thing to a shipped harness-as-framework: compaction, todo management, file-based memory, OpenTelemetry instrumentation, a shell executor (with a deny-list it explicitly calls "a UX pre-filter, not a security boundary"), and background agents. Useful as a concrete reference for what a harness runtime ships with — and which defaults you must override.

Weight: vendor docs; read the overview page, not every sample. Used in: Modules 00, 07, 12, 16.

12-Factor Agents

Repo HumanLayer · github.com/humanlayer/12-factor-agents

Principles for production LLM applications, predating the harness vocabulary but overlapping heavily. Own your prompts, own your control flow, treat tools as structured output, make state explicit.

awesome-harness-engineering

Repo github.com/walkinglabs/awesome-harness-engineering

Link collection. Useful for finding what appeared after this course was compiled.

AI-Harnesses

Repo Daniel Rosehill · github.com/danielrosehill/AI-Harnesses

Comparative notes across harness implementations. Useful for seeing how the same primitives get named differently by each tool.

Named but not read closely

Flagged for honesty — these are referenced in the course but I did not verify their contents in depth, so treat any claim attributed to them as second-hand:

  • ETH Zurich study on AGENTS.md efficacy (2026) — cited in Module 04 as a pointer only. The claim that instruction-file benefits are more modest than practitioner enthusiasm suggests is not verified here.
  • Terminal Bench 2.0 leaderboard — the ~#33 versus ~#5 figures circulate through Trivedy and HumanLayer. I did not check the leaderboard directly. Ranks approximate; magnitude corroborated independently.
  • OpenAI on harness engineering — the six-hour Codex run figure comes from their published material via secondary citation.
  • arXiv 2602.11988 — retrieved during the source sweep, not load-bearing for any claim in these lessons.
