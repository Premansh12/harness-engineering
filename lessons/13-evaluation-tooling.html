Evaluation tooling

Harness engineering is as much about evaluation as about building. This module surveys the three tools the field points to — LangSmith, harness-evals, Langfuse — and runs a minimal eval you can actually execute, so the shape is clear before you pay for a platform.

Section 1The shape all evaluators share

Every eval framework, commercial or not, has the same skeleton:

  • Golden — what you author: an input, the expected output, optional context.
  • Target — the system under test (your agent).
  • Metric — a function returning a score, usually normalized 0.0–1.0.
  • Baseline comparison — did this version beat the last one?

LangSmith, harness-evals, and Langfuse differ in packaging and where they run, not in this shape. Learn the shape once; the tools are interchangeable front-ends.

Section 2LangSmith

LangChain's platform for online + offline evaluation. Key ideas from their docs:

CapabilityNote
Offline + online evalsScore trajectories, not just final answers
LLM-as-judgeBootstrap labels, then refine with humans
CI/CD integrationpytest / Vitest / GitHub workflows; fail the build on score drop
Dataset from tracesCapture production, sample into a dataset
Framework-agnosticNot tied to LangChain; SDK sends traces from any stack

Section 3harness-evals

An open-source framework (Apache 2.0) with a distinctive design: every metric belongs to one of five dimensions, and any suite auto-produces a radar chart grouped by dimension.

DimensionQuestionExamples
CorrectnessIs it right?ExactMatch, TaskCompletion
GroundednessSupported by evidence?Faithfulness, ContextPrecision
SafetyViolated policy?PII, PromptInjection, Hallucination
TrajectoryGood path?PlanAdherence, StepEfficiency
PerformanceFast & cheap?Latency, TokenCost

Its core concepts map onto the skeleton above: Golden → EvalCase → BaseMetric.measure() → evaluate() → compare_to_baseline(). Safety metrics are reported separately and never averaged — a useful discipline.

Section 4Langfuse

Langfuse's academy frames evaluation through experiments: pick a variable, run your dataset through two versions, compare. Their "where to start" advice is the same as Module 08's: start manual. 20–30 real examples, both conditions, traces side by side, read before you score. Scores then make comparison concrete — win rates, cost/latency tradeoffs. Quality, price, and speed rarely move together; experiments show the pulls in your data.

Quiz · Module 13

The three tools (LangSmith, harness-evals, Langfuse) differ mainly in…
Why: All three follow golden → target → metric → baseline. Learn that shape and the tools are front-ends; pick by where it runs (self-host, cloud, OSS).
harness-evals groups every metric into five dimensions and…
Why: Correctness / Groundedness / Safety / Trajectory / Performance. Safety metrics are kept apart so a safe-but-wrong run doesn't get masked by a high average.
Langfuse's "where to start" advice matches which earlier module?
Why: Both say: begin with a small manual comparison, read real outputs, then encode a metric once intuition exists. Scores without reading are easy to misread.
