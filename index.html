Harness Engineering

The model is one input. Everything else — the loop, the tools, the context policy, the state, the verification, the sandbox — is yours. That surface area is where most of the leverage in agent work now sits, and it has almost no textbook.

Why this exists

For two years the public conversation about AI engineering has been about models: which one is smartest, which hallucinates less, what happens at the next checkpoint. That conversation is fine as far as it goes, and it is missing the other half of the system.

Agent = Model + Harness. If you're not the model, you're the harness. Vivek Trivedy, The Anatomy of an Agent Harness, March 2026

The sharpest available evidence for how large this effect is comes from Terminal Bench 2.0. The same Claude Opus 4.6 weights place roughly #33 running inside Claude Code and roughly #5 running inside a custom harness. Nothing about the model changed. What changed was the tools, the prompt, the feedback signals, and the loop. Viv Trivedy's team moved an agent from Top 30 to Top 5 by editing only the harness.

That gap is the subject of this course.

How to read the claims here

Harness engineering is about eighteen months old as a named discipline and the literature is thin. Most of what follows is practitioner field-report, not controlled study. Where a claim comes from a measured result I say so and give the number. Where it is a working heuristic that has not been isolated, I flag it. Treat the second category as a hypothesis you should ablate in your own setup — Module 09 teaches you how.

What you will be able to do

  • Name every component of a harness and state which behaviour each one exists to deliver — and delete the ones that cannot answer that question.
  • Measure the context cost of your own tool inventory, verification signals, and subagent topology, in characters, rather than guessing.
  • Design handoff artifacts that survive a context reset without the next agent quietly declaring victory.
  • Build back-pressure that is deterministic — signals the model cannot reason its way past.
  • Reason correctly about credential isolation under prompt injection, where "the model probably won't do that" is not a control.
  • Run an ablation, read the table, and delete harness code that a model upgrade has made redundant.

How the walkthroughs work

Every module ships with a script under lab/. They run against a FakeModel that replays a scripted trajectory, so each one is deterministic, offline, free, and finishes in under a second. You are studying the harness, not the model — a scripted model is the correct instrument, because it holds the only variable you are not testing perfectly constant.

terminal
cd ~/harness-engineering
python3 lab/w01_loop.py

Python 3 standard library only. No install, no key, no network. At the end of Module 10 you swap the fake model for a real one by implementing a single method.

A standing caution

This field's canon is fifteen months old and its strongest claims come from teams shipping products they also sell. Anthropic's harness posts are excellent engineering writing and also marketing for Claude. The LangChain post defines a term while selling a framework. Read for mechanism, discount the framing, and verify against your own ablations.
