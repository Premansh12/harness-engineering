Back-pressure: silent success, loud failure

The single most measurable win in the whole course. A verbose green test run costs 112x the context of a silent one. And the agent cannot grade its own work — so verification has to live outside the loop.

Section 1The 112x number

Run it
terminal
python3 lab/w05_backpressure.py
real output · lab/w05_backpressure.py
verbose green run : 10,011 chars  (logs + "PASSED" banners)
silent green run  :     89 chars  ("exit=0")
ratio             : 112x

A test suite that prints everything it does, on success, spends 112 times the context of one that prints nothing on success and only speaks on failure. On a long task, that difference is the difference between fitting in the window and overflowing it (Module 03). The principle: be silent on success, loud on failure. That is back-pressure done right.

On success, say nothing. The context you save is the agent's working memory.

Section 2Guides versus sensors

Böckeler's framing: guides push the agent toward behaviour (prompts, instructions, examples); sensors observe whether it worked (tests, checks, signals). Verification is a sensor. The trap is treating a guide as a sensor — assuming the agent did the thing because you told it to.

Two kinds of sensor: computational (a test, a type-checker — deterministic, trustworthy) and inferential (an LLM judging whether the output is right — itself a model, itself fallible). The hierarchy of trust: computational > inferential. Use a test when you can; reserve LLM-judges for where no test exists.

Section 3The agent cannot grade its own work

This is the load-bearing claim. An agent that writes code and then reports "it works" is grading itself — and self-grading is biased and unverifiable. The harness must evaluate completion with something the agent cannot manipulate: a test it didn't write, a checker outside the loop, a human gate.

An agent cannot grade its own work. Verification is a sensor that lives outside the loop.Course principle, from Böckeler's guides/sensors and Anthropic's self-evaluation failure

HumanLayer's 4,000 lines of passing tests story is the cautionary version: an agent generated a test suite that passed — 4,000 lines of green — while the actual feature was broken. The tests verified the wrong thing. The lesson is not "don't use tests"; it's "the test must check the requirement, not the agent's self-image."

Section 4Wiring it to a hook

The contract from HumanLayer: verification should be silent on success, actionable on failure. Wire it as a hook — fire after each tool call or each step, fail loud, never spam on green. The walkthrough's silent-green policy is the minimal version of that hook.

Verification lives…Trust
Inside the loop, self-reportedNone — the agent grades itself
Outside the loop, computationalHigh — a test it didn't write
Outside the loop, LLM-judgedMedium — inferential, still a model
Human gateHighest for irreversible actions
