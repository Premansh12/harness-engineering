Long horizons: subagents and loops

One agent over a thousand steps rots (Module 03). The standard fix is to spin subagents that each run a short, clean loop — a context firewall. It costs more total tokens, and that is the point.

Section 1The context firewall

python3 lab/w06_subagents.py
real output · lab/w06_subagents.py
parent context after delegating:
  without subagent : 48,200 chars  (carries ALL child steps)
  with subagent    :  1,840 chars  (only the result)
  parent-context reduction : 96.2%

A subagent runs its own short loop, then hands back only a summary. The parent never sees the child's 40 steps of reasoning — so the parent's context stays clean. That 96.2% reduction is a firewall: each worker starts from a near-empty window, does its job, returns a result.

Note the trade: total tokens go up. The child still spent 48k; the parent just doesn't carry it. You pay for isolation. That is the deal — and on a long horizon, a clean context beats a cheap one.

Each subagent burns its own context; the parent carries only the returned result.

Section 2The Ralph loop

The recursive pattern (named after Ralph, the recursive agent in the literature): a top-level agent decomposes a goal, spawns subagents, collects results, and re-plans. Three requirements for it not to collapse:

  • Bounded depth — recursion must terminate; a loop that spawns itself forever is the infinite-loop failure from Module 01.
  • Clean handoff — each subagent gets a self-contained task and returns a verifiable result (Module 04).
  • A real stop — the top level decides completion from results, not from the model's mood (Module 05).

Section 3Where harness engineering ends

Subagents are a loop pattern — orchestration. Once you are coordinating many agents, you are doing multi-agent orchestration, which is adjacent to but distinct from single-agent harness engineering. The harness lessons (tools, context, verification, safety) still apply inside each subagent; the orchestration layer is a separate concern. Don't confuse "many agents" with "a better harness" — they solve different problems.

"A software factory is harnessed loops at scale. You can run the loop with humans in it (light factory): trading judgment and concentration against speed and breakage. Or you can ignore the humans…"

A subagent is called a "context firewall" because…
Why: The parent context is protected from the child's step-by-step token growth. The firewall is the boundary at which only the summary crosses back.
For a recursive (Ralph) loop not to collapse, which is NOT one of the three stated requirements?
Why: The three are bounded depth, clean handoff, and a real stop. A bigger window doesn't prevent runaway recursion — it just delays the rot.
Multi-agent orchestration is described here as…
Why: Orchestration coordinates agents; harness engineering builds the runtime inside each. They solve different problems, and conflating "many agents" with "better harness" is a category error.
