Harness Engineering · Module 02

Tools, bash, and the context tax

Tools are how a model acts on the world. But every tool you register costs context on every step — before the agent has read your task. This module measures that cost and gives a decision rule for when a tool belongs in the harness at all.

Reading + walkthrough + quizlab/w02_tools.py45 minCompiled by Premansh Panigrahi

Section 1The filesystem is the primate's thumb

Before fancy MCP servers, there is one tool that does most of the work: bash. The model writes code, runs it, reads the result. The filesystem is the shared scratchpad between the model's imagination and reality. Anthropic's managed-agents work treats a sandboxed working directory as the agent's body; everything else is an appendage.

But tools are not free. Each registered tool ships a description so the model knows when to call it — and that description is sent on every single step, whether or not the tool is used. That is the context tax.

That is the headline number. Before the agent has read a single line of your task, 6,577 tokens are already spent describing tools it may never call. Context is a finite, degrading resource (Module 03) — and you are burning 6% of a 100k window on overhead before doing any work.

Section 3The CLI-over-MCP decision rule

HumanLayer's most concrete finding: they replaced a Linear MCP server with a CLI section in CLAUDE.md. Why? An MCP server ships a large tool schema the model must reason about every step. A CLI command, documented in the system prompt, costs nothing at inference and the agent shells out to it. The rule they landed on:

Use an MCP server when…Use a CLI + prompt when…
The tool needs dynamic discovery or streamingThe tool is a thin wrapper over a known command
The interface changes often and you want it self-describingThe command surface is stable
The model must browse an API's shape at runtimeYou can describe it once in prose

The counter-intuitive part: fewer, plainer tools beat a rich schema. A crowded toolbelt doesn't just cost context — HumanLayer also reports that restricting a subagent's toolbelt did not help (a negative result, and an unusual one), while a clear CLI description did.

Section 4Allow-lists: the harness decides, not the model

The walkthrough's make_bash_tool is allow-listed: the harness permits echo, ls, cat, pytest, python3, grep, wc and blocks everything else. A model that asks for rm -rf / gets BLOCKED — not because the model is wise, but because the harness refuses. This is the theme of Module 07, introduced here because tool access is where it first shows up.
