Harness Engineering · Module 04

State, memory, and the shift change

Long tasks don't fit in one context window. The harness has to persist state across compaction and across agents. The handoff artifact is the contract that makes a later agent pick up where an earlier one stopped — and the naive version fails in a specific, documented way.

Section 1Compaction versus context reset

Two different problems get the same word. Compaction shrinks the current context (Module 03) — it loses detail. Context reset is different: it empties the context on purpose and reloads a curated summary, so the agent starts a new stretch with a clean window and a written record of where things stand. Anthropic used resets to fight "context anxiety" — the observed behaviour where an agent, deep in a long context, decides the task is done and wraps up early.

The cost: a reset throws away the working context. So the summary it reloads is the agent's memory. If that summary is wrong, the agent proceeds on a false picture. That is the whole risk of the shift change.

Section 2The handoff artifact

When one agent (or one stretch of an agent) hands off to another, it writes a handoff artifact: a structured record of what was done, what's left, and what "done" means. The walkthrough builds one and makes completion machine-checkable — a later agent can verify the claim rather than trust the prose.

handoff artifact written:
  done:    3/5 subtasks
  proof:   tests/subtask_1..3 pass
  blocker: subtask_4 needs API key

later agent reads artifact:
  claims "3/5 done" -> VERIFIED (tests pass)
  claims "blocked on key" -> ACTIONABLE

The artifact is structured, not a paragraph, because structure is what a later agent — or a test — can parse. Markdown prose is for humans; JSON with explicit fields is for machines. This module's rule: handoffs are contracts, write them as data.

Section 3The failure: "done" by proximity

The documented failure: a later agent reads a handoff showing substantial progress, sees the job is "mostly done," and declares completion without checking the remaining subtasks. It mistakes progress for completion. The fix is in the artifact design — completion must be independently checkable, not asserted. The walkthrough's verifier refuses to accept "done" unless the proof field actually passes.

Section 4Initializer agents

The complementary pattern: an initializer agent runs first, sets up the workspace, writes the plan and the memory files, then hands to the worker. The worker never sees the full messy beginning — it starts from a curated state. This is how you keep a long task from drowning in its own early context. Microsoft's Agent Framework ships exactly this shape: a todo provider, a file-memory provider, and per-call history persistence so a crash mid-run is recoverable.

State crosses the boundary as data. The receiver verifies, it does not assume.
