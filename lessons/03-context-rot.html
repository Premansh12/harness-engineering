Harness Engineering · Module 03

Context rot and what to do about it

Context is a finite, degrading resource. Three policies manage it — none, compaction, and offload — and they are not interchangeable. One of them quietly destroys information. The needle test shows you which.

Reading + walkthrough + quizlab/w03_context.py50 minCompiled by Premansh Panigrahi

Section 1Context is not memory

The context window is what the model can see right now. It is bounded and, once full, something has to give. "Context engineering" (a sub-discipline of harness engineering) is the craft of deciding what occupies that space at each step. LangChain's taxonomy names four moves: write (add info), select (choose what's visible), compress (shrink what's there), isolate (keep it out of the main thread).

The failure mode is "context rot": the window fills with low-value tokens, crowding out what the agent needs, and decisions get worse. Every harness picks a policy. We run all three against one trajectory.

none          46,120       yes (everything kept)
compaction    8,910        NO  (summarized away)
offload       9,240        yes (on disk, fetched)

Read that table carefully. None keeps everything — works, but the window is huge and will overflow on a longer task. Compaction shrinks the window 5x — but the "needle" (a specific fact the later step needs) was summarized away and is gone. Offload shrinks almost as much, and the needle is still recoverable from disk.

This is the single most important distinction in the module: compaction destroys; offload preserves. They look identical on the size metric. They are opposite on the information metric.

Compaction and offload shrink the window similarly. Only offload keeps the needle.

Section 3The needle test

How do you know a policy is safe? Plant a "needle" — a specific fact the agent will need many steps later — then check it survives. If compaction ate it, the policy is unsafe for any task where later steps depend on earlier detail. Offload passes; compaction fails. This is the test the walkthrough runs, and it is the test you should run on your own context policy before trusting it.

Microsoft's Agent Framework exposes exactly this as a toggle: MaxContextWindowTokens + DisableCompaction. The harness that ships with it compacts by default when a budget is set — meaning the safe default is the destructive one, and you must opt into preservation. That is a real product getting this backwards by default, which is why you measure it yourself.

Quiz · Module 03

Compaction and offload both shrink the context window. What is the critical difference?
Why: The needle test is the discriminator. Both hit ~9k tokens, but the offloaded needle is still retrievable; the compacted one was summarized away. Same size, opposite information outcome.
The "needle test" in this module is used to…
Why: Plant a specific fact early, require it late, and see if the policy kept it. If compaction ate it, the policy is unsafe for tasks where later steps depend on earlier detail.
Microsoft's Agent Framework compacts by default when a token budget is set. The module's reaction is…
Why: Default-on compaction means the destructive policy is active unless you intervene. So you must measure your own policy — don't trust the default to preserve what later steps need.
LangChain's four context moves are write, select, compress, isolate. "Offload" is an instance of which?
Why: Offload moves detail out of the main context onto disk and fetches it when needed — that is isolation. Compress would shrink it in place and risk losing it; offload keeps the original.
