Defining the harness

The practitioner's definition (Module 00) said what a harness does. The research literature tries to make that precise — necessary and sufficient conditions, an inclusion/exclusion test, and a boundary against the five things people confuse it with. This module walks the academic definition.

Reading + flip cards + quizno walkthrough40 minCompiled by Premansh Panigrahi

Section 1Why a precise definition matters

"Agent harness" circulates widely but loosely. Sometimes it means the whole product (Claude Code). Sometimes the eval scaffold (SWE-bench). Sometimes a framework, an SDK, an IDE plugin, or an orchestrator. Without a reference definition, you cannot compare systems, replicate results, or even argue about them — everyone means a different thing by the same word.

Macedo's 2026 paper, "What makes a harness a harness" (arXiv:2606.10106), sets out to fix this by building a constitutive definition — one that states the necessary and sufficient conditions for a system to be an agent harness — and then operationalizing it as an inclusion/exclusion test.

Section 2The genealogy, and why it helps

The paper reconstructs the term's lineage: the horse's tack → the classic test harness → the ML evaluation harness → the agent harness. The through-line: a harness is something that holds a system in place so you can drive and measure it. The agent harness holds a model so it can act and be evaluated. That etymology is not trivia — it explains why "eval harness" and "agent harness" share a name but are different objects (one measures, one acts).

Section 3The boundary test

The paper applies its definition to six real systems and to deliberate edge cases, and reports the test "includes and excludes consistently." The five distinctions that matter:

Agent
Model + loop + state, acting in an environment. The thing the harness makes possible — not the harness itself.
Agent SDK
A library of primitives you assemble. A toolkit you build a harness from, not the runtime.
Agent Framework
Opinionated, batteries-included scaffolding. In practice this often IS the harness (LangGraph, Agent Framework).
Agent Harness
The runtime that drives the loop, tools, context, safety. The target of the definition.
Eval harness
Scaffold that runs an agent against tasks to measure it. Measures, does not act — a different object.
Orchestrator
Coordinates multiple agents. Sits above the single-agent harness, not inside it.

Section 4The research agenda: design tensions

The paper closes with a research agenda organized by design-tension axes — pairs of properties that pull against each other and that any harness must trade off:

TensionThe two pulls
Generality ↔ SpecializationOne harness for many tasks, vs. a harness tuned to one
Control ↔ AutonomyHuman-in-the-loop safety, vs. unattended speed
Transparency ↔ PerformanceFull traces you can audit, vs. lean context that runs fast
Stability ↔ AdaptabilityA harness that doesn't drift, vs. one that evolves with the model

These axes are the research frontier. Module 15 (self-evolving harnesses) sits squarely on the stability/adaptability axis.

Section 5Check your understanding

Quiz · Module 10

Macedo's goal is a "constitutive definition" — meaning it states…
Why: Constitutive = what makes something that thing. Necessary-and-sufficient conditions let you include and exclude cases consistently, which is what the loose usage lacks.
Why do "eval harness" and "agent harness" share a name but differ?
Why: The genealogy runs tack → test harness → ML eval harness → agent harness. The shared idea is holding a system in place; the eval harness measures, the agent harness acts.
On the stability ↔ adaptability tension, self-evolving harnesses (Module 15) pull toward…
Why: An evolving harness changes with the model, which is the adaptability end. The tension is that evolution risks drift away from a stable, auditable baseline.
Which is the paper's main reason a precise definition is needed?
Why: Without a shared definition, "harness" means different things to different authors, and you cannot compare or reproduce work. The definition is an instrument, not a branding exercise.
